# Faza 5 — radnički agent + WOL + pokretanje programa — plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** `atlas-agent` — mala Python skripta u radnikovoj sesiji koja se spaja VAN prema serveru (bez portova na radnom stroju), prima naredbe iz uske allowliste (pokreni odobreni program, uredno ugasi, javi status, uključi WOL) i sve ostalo odbija. Server budi radna računala magic paketom pri dizanju. Chat "kod Ane otvori X" → veza radnik↔uređaj (faza 2) → agent.

## Ključne sigurnosne odluke (RCE na uredska računala — maksimalan oprez)
- **Transport (ponytail deviation od "wss:8443"):** agent se spaja VAN preko HTTPS long-polla (`GET /agent/poll` čeka naredbu, `POST /agent/result` vraća ishod) — ISTI intent (odlazna veza, nula portova na radnom stroju, token auth), NULA novih depsa (worker WebSocket klijent bi tražio dep). Upgrade path: pravi wss kad zatreba niska latencija.
- **Nikad proizvoljna komanda preko žice.** Server šalje samo `program_key` (npr. "preglednik"), NE naredbeni string. Agent drži VLASTITU lokalnu mapu key→izvršni put (postavljena pri instalaciji na tom stroju) i odbija nepoznat key. Tako ni kompromitiran server ne može pokrenuti proizvoljan kod na radnicima.
- **Tvrda allowlista radnji U AGENTU:** {run_program(key iz lokalne mape), shutdown, enable_wol, status}. Sve izvan toga agent odbija bez obzira što server pošalje. Nema eval/shell — argv liste.
- **Token po uređaju:** izdaje se u Postavke→Uređaji, hash u bazi (kao lozinke), opoziv = uređaj gluh odmah (svježa provjera pri svakom pollu). Token nosi device_id; agent ga šalje u Authorization.
- **Ovlasti izdavanja/naredbi:** samo owner (strojno kao i faza 4). Enqueue naredbe: admin+ uz vidljivost uređaja (veza radnik↔uređaj iz faze 2).

## Global Constraints
