## B1 — Sadržaj se shrink-wrapa i centrira 🔴

**Gdje:** `ragspine/web/templates_ui.py:58` (uz `:62`)

```css
/* :58 */ .container{max-width:1200px;margin:0 auto;padding:1.5rem 1.25rem 3rem}
/* :62 */ .layout{display:grid;grid-template-columns:220px 1fr;min-height:100vh}
```

`<main class="container">` je **grid item**. Auto-margine na grid itemu ukidaju
`stretch` poravnanje — element se tada dimenzionira na `fit-content` i centrira
u svojoj gridovskoj ćeliji, umjesto da ispuni stupac.

**Posljedica:** sadržaj lebdi u sredini s asimetričnim mrtvim prostorom, a
**širina se mijenja od stranice do stranice** ovisno o sadržaju. Izmjereno na
istom prozoru: Chat 768px lijevo, Postavke 613px, Nadzorna ploča 505px.

**Mjerenje uživo** (`/ui/racunalo`, prozor 1912px):

```js
var m = document.querySelector('main.container'), r = m.getBoundingClientRect();
// viewport=1912  sidebar=220  main.left=569  main.width=995
// centrirano: 220 + (1692-995)/2 = 568,5  ✔ poklapa se
```

**Popravak [PROVJERENO UŽIVO]** — razdvoji ulogu grid itema od uloge okvira za
čitljivu širinu. Ne popravljaj samo `margin`, jer `max-width:1200px` treba ostati:

```css
.container{max-width:1200px;padding:1.5rem 1.25rem 3rem}
.layout > .container{justify-self:stretch;width:100%;margin-inline:0}
```

Ako se centriranje želi zadržati, uvedi unutarnji omotač:
`main{justify-self:stretch;padding:…}` + `main > .inner{max-width:1200px;margin-inline:auto}`.

**Provjera:** nakon popravka `main.left` mora biti **220** (odmah do sidebara),
a `main.width` **1200** — konstantno na svim ekranima.

```js
// očekivano poslije: left=220 width=1200
var r = document.querySelector('main.container').getBoundingClientRect();
console.log(Math.round(r.left), Math.round(r.width));
```

**Test:** vrijedi dodati u `tests/test_ui.py` provjeru da CSS ne sadrži
`margin:0 auto` u pravilu koje se primjenjuje na `.layout` dijete.

## B2 — Literalni `\u010d` umjesto `č` 🔴

**Gdje:** `ragspine/web/templates_preflight.py`, linije **115, 119, 130, 131, 132**

```python
115:  <h1>Ra\\u010dunalo i modeli</h1>
119:    <h2>Stanje ra\\u010dunala</h2>
130:    <h2>Lokalni modeli \\u2014 rangirano po llmfit score-u</h2>
131:    <p class="muted">llmfit mjeri tvoje ra\\u010dunalo i za svaki model ra\\u010duna kvantizaciju
132:       koja stane, o\\u010dekivanu brzinu (tok/s) i ocjenu. Prvi red \\u2014 najbolji.</p>
```

**Uzrok:** `body` je **obični** trostruki string (ne raw, ne f-string). `\\u010d`
u Python izvoru daje literalnih 6 znakova `\u010d` u izlaznom HTML-u. HTML ne
poznaje `\u` escape sekvencu, pa je ispisuje doslovno.

Korisnik na `/ui/racunalo` vidi:

> **Ra\u010dunalo i modeli**
> Lokalni modeli \u2014 rangirano po llmfit score-u

**Zašto je promaklo:** u istom fajlu, linije 7-11, 58-59, 91-93 koriste isti
zapis i **rade ispravno** — jer su unutar JavaScript stringova, gdje je `\u`
valjan escape. Greška je samo u HTML kontekstu.

**Popravak:** upiši slova izravno (fajl je već UTF-8):

```python
115:  <h1>Računalo i modeli</h1>
119:    <h2>Stanje računala</h2>
130:    <h2>Lokalni modeli — rangirano po llmfit score-u</h2>
131:    <p class="muted">llmfit mjeri tvoje računalo i za svaki model računa kvantizaciju
132:       koja stane, očekivanu brzinu (tok/s) i ocjenu. Prvi red — najbolji.</p>
```

**⚠ Ne diraj** linije 7-11, 58-59, 91-93 — one su u JS-u i ispravne su.

**Provjera / regresijski test:**

```python
def test_preflight_bez_literalnih_escapeova():
    from ragspine.web.templates_preflight import preflight_page
    html = preflight_page()
    head = html.split("<script>")[0]          # samo HTML dio, bez JS-a
    assert "\\u" not in head, "literalni \\u escape iscurio u HTML"
```

function toast(text, kind) {           // kind: 'ok' | 'warn' | 'bad'
  var box = document.getElementById('toasts');
  if (!box) {
    box = document.createElement('div');
    box.id = 'toasts';

}

## B10 — Putanja `/v1/chat/completions` je ušivena u klijenta 🟠

**Gdje:** `ragspine/core/llm.py:122` (i `:104` za anthropic)

```python
url = f"{base}/v1/chat/completions"
```

Zbog toga `base_url` **mora biti gola domena bez verzijskog puta**. Ta konvencija
radi za sve što ima compat put oblika `{origin}/v1`:

| Provider | `base_url` koji radi |
|---|---|
| DeepSeek | `https://api.deepseek.com` |
| Moonshot / Kimi | `https://api.moonshot.ai` |
| Groq | `https://api.groq.com/openai` |
| Mistral | `https://api.mistral.ai` |
| OpenRouter | `https://openrouter.ai/api` |
| xAI (Grok) | `https://api.x.ai` |
| Together | `https://api.together.xyz` |

**Pada za Google Gemini.** Gemini **ima** OpenAI-kompatibilan endpoint — ali na
putu `/v1beta/openai/`, ne `/v1/`
([Google, OpenAI compatibility](https://ai.google.dev/gemini-api/docs/openai)).
Upiše li se `https://generativelanguage.googleapis.com/v1beta/openai`, klijent
gradi `…/v1beta/openai/v1/chat/completions` → 404.

**⚠ Ovo ispravlja raniju pretpostavku.** Ne treba Gemini adapter. Treba **polje
„put" uz `base_url`** u katalogu providera, s `"/v1/chat/completions"` kao
zadanom vrijednošću:

```python
url = f"{base.rstrip('/')}{path}"     # path dolazi iz kataloga
```

Ista izmjena unaprijed pokriva Azure OpenAI i svakog budućeg providera s
nestandardnim putem — manja je od adaptera i ne piše se dvaput.

**Provjera:** postojeći provideri moraju i dalje raditi s praznim/zadanim `path`;
Gemini radi s `path="/v1beta/openai/chat/completions"`.

## B12 — Lokalni OpenAI-kompat serveri osim Ollame ne prolaze 🟡

**Gdje:** `business/model_settings.py:19` (`_validate_remote_url`) + `core/llm.py:27`

```python
# model_settings.py:19
if p.scheme != "https":
    raise ValueError("base_url mora biti https za Claude/OpenAI")

# llm.py:27 — Ollama se prepoznaje samo ovako
if ":11434" in base_url or base_url.rstrip("/").endswith("/api"):
```

**Posljedica:** LM Studio (`:1234`), llama.cpp i vLLM prepoznaju se kao „openai",
pa validacija odbije `http://127.0.0.1:1234`. Na samohostanom programu za uredski
LAN to je stvarno ograničenje — Ollama je jedini lokalni server koji prolazi.

**Zašto mislim da je uvjet prestrog:** namjera pravila (vidljiva iz komentara na
`:16-18`) je *spriječiti da spremljeni API ključ ode na napadačev ili interni
host*. Lokalna petlja bez ključa ne nosi taj rizik.

**Prijedlog:** dopustiti `http` kad su **oba** uvjeta ispunjena — host je loopback
ili privatna adresa **i** polje za ključ je prazno. Ostaviti `https` obaveznim čim
ključ postoji.

**Ovo je sigurnosna odluka, ne UI odluka — prijavljujem je, ne predlažem gotov
patch.** Ako procijeniš da rizik ne vrijedi, reci pa ću u sučelju napisati da su
lokalni modeli isključivo preko Ollame.

## Što NE dirati — preporuke protiv izmjena

Nalazi gore su stvari koje treba popraviti. Ovo je obrnuto: mjesta gdje bi izmjena
izgledala logično, a ja preporučujem da se **ne** radi. Zapisano da netko za pola
godine ne potroši dan na posao koji je već odbačen.

**1. Ne preimenovati `/ui/*` rute u `/postavke/*` 🔴 najvažnije**

Nova arhitektura (`ARHITEKTURA.md §4`) slaže 13 ravnih kartica postavki u stablo od
6 grupa i 20 listova. Logično bi bilo da URL prati stablo:
`/ui/model` → `/postavke/model/provider`.

**Nemoj.** Korisnikov zahtjev je bio *„vlastiti URL po stranici"* — a to **već
postoji**: svaka podstranica postavki ima svoj `/ui/*`. Preimenovanje bi značilo:

- ~20 izmijenjenih ruta u `api.py`
- redirecti sa starih na nove, inače pucaju spremljene zabilješke u uredu
- izmjene u svakom `templates_*.py` koji linka „← Postavke"
- nula vidljive koristi korisniku

Grupiranje je posao **stabla u sučelju**, ne putanje. Stablo grupira, URL ostaje
gdje jest. Ako se ikad radi verzioniranje API-ja, tad se preimenuje — ne prije.

**2. Ne razdvajati `/ui/posta` na dvije rute zbog stabla**

U stablu su E-pošta i Telegram dva lista, jer su to dvije nepovezane veze koje su
danas spojene u jednu karticu samo zato što je mreža od 13 bila prepuna. **Ali obje
za sada gađaju isti `/ui/posta`**, usidrene na `#posta` i `#telegram`. Razdvajanje
rute je posao za kasnije, ako se ekran ikad prepuni — ne preduvjet za novo sučelje.

**3. Ne graditi ekran za uređivanje kataloga providera**

Katalog iz `ARHITEKTURA.md §5.1` je **statična tablica u kodu**, ne tablica u bazi.
Provideri se mijenjaju par puta godišnje; katalog u bazi znači migraciju, CRUD rute
i ekran za uređivanje koji nitko neće otvoriti. Opciju „Ručni unos…" u padajućem
izborniku pokriva sve što katalog ne zna — to je dovoljan izlaz.

**4. Ne upisivati popis naziva modela u kod**

Ponovljeno iz B11 jer je najlakše pogriješiti: `claude-…`, `gpt-…`, `gemini-…`
zastarijevaju brže od svega ostalog u projektu. Tvrdo upisan popis je zajamčeno
kriv za pola godine. Tipični modeli idu kao *prijedlog* u `<datalist>`, a istina se
dohvaća s `GET /v1/models` kod samog providera.
